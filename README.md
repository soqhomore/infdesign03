## 공개 점검 해제·Vercel 체험 연결 · 2026-11-10 최신

사용자가 공개 주소의 점검 화면을 해제하고 게임을 연결하도록 승인했다. 이전의 공개 점검 화면 유지 지침은 이번 요청으로 대체된다. index.html과 interview.html은 현재 3D 면접 여정으로 교체했다. local/room.html을 원본으로 npm run build가 공개 진입점과 dist 산출물을 생성한다.

기존 Node API는 로컬 전용이고 메모리 세션에 의존한다. 구현 선택으로 공개 버전은 기존 준비 대사 규칙을 브라우저에서 실행한다. 대사 규칙은 assets/demo/interview-model.js로 추출해 로컬/공개 버전이 공유한다. 공개 버전은 AI 미사용·준비 대사임을 안내하며 답변을 브라우저 메모리에만 두고 서버나 AI로 전송하지 않는다. 음성 인식의 브라우저 서비스 전송 가능성과 기기 TTS는 기존과 같다. 로컬 /local/의 AI/API 모드는 유지한다. 새 유료 서비스나 공개 AI API는 도입하지 않았다.

vercel.json은 Other 프레임워크와 npm run build, 출력 dist를 명시한다. 공개 /, /interview.html, 정적 배포의 /local/·/local/room.html에서 같은 공개 체험을 시작한다. 실행 파일·assets·vendor만 복사하고 서버 소스·.env·node_modules·기획/원본 자료는 배포 폴더에 넣지 않는다. dist와 .vercel은 Git에서 제외한다.

검증: npm run build, npm run check 및 npm test 전체 112개 통과. 준비 대사 서버와 공개 엔진의 다회 대화 일치, 공개 클라이언트의 서버 요청 없는 종료, 중복 요청/만료/취소/입력 검증, 공개 진입점/비공개 파일 제외/출력 폴더 보호와 실행 의존 경로를 검사했다. 기존 여정 lifecycle 3시나리오도 통과했고 독립 읽기 전용 리뷰에서 중대한 오류를 찾지 못했다.

현재 환경에서 GitHub DNS와 브라우저 접근 호스트가 연결되지 않아 원격 업로드·Vercel 빌드·실제 WebGL 화면은 확인하지 못했다. 배포 완료로 간주하지 않는다. GitHub 푸시와 Vercel 빌드 완료 뒤 실제 사이트를 확인해야 한다. 상세 기록: docs/reviews/2026-11-10-public-release.md 및 public-release-verification.json.

## 음성 누락·진단 보완 · 2026-11-10 최신

면접관 음성 출력은 외부 TTS가 아니라 브라우저/기기의 한국어 SpeechSynthesis를 사용한다. 코드 재현 검사에서 일시정지 중 도착하거나 끊긴 대사를 복귀 후 읽지 않는 경로, 아직 비어 있는 voiceschanged 이벤트를 한 번 받은 뒤 음성 로딩을 포기하는 경로를 확인했다. 최신 대사만 복귀 후 한 번 읽도록 보완하고, 한국어 목소리를 최대 3초 기다리되 중간 빈 이벤트는 무시한다. 완료한 대사는 반복하지 않으며 음성 끄기·제출·초기화 때 대기 중 대사를 폐기한다.

일시정지 설정에 목소리 시험과 선택된 목소리/재생 상태를 추가했다. 시험 음성은 메뉴가 열린 동안에도 재생할 수 있고, 복귀 시 시험을 끊고 보류된 면접 대사를 읽는다. 재생 차단·네트워크·한국어 음성 미확보를 안내한다. 시작 실패 시 한 번만 재시도하고 끝내 실패하면 알리며, 종료/취소 이후 늦은 음성 이벤트를 무시한다. 기존 자연스러운 기기 음성 우선순위는 유지한다.

검증: npm run check 통과, npm test 전체 97개 통과. 실제 사용자 기기의 무음 원인을 확정한 것은 아니다. 브라우저 접근 호스트가 연결되지 않아 실제 음성 출력·마이크·WebGL은 이번 작업에서 미검증이다. voice-verification.json 참고. 이전 버그·성능 점검의 1.5초/한 번의 이벤트 대기와 복귀 후 다음 발언부터 재생한다는 설명은 이전 상태다.

자연스러운 목소리는 고정 대사를 미리 생성/녹음한 파일로 재생하고, 동적 AI 답변만 서버 TTS로 읽는 방식을 제안한다. 감정 연기를 지원하는 ElevenLabs 등을 후보로 조사했지만 사용자 확정이나 서비스 연결·유료 호출은 하지 않았다. 공급자/목소리별 실제 한국어 청취가 필요하다.

## 입체 침구·햇빛·작은 성취 대사 · 2026-11-10 최신

창 안쪽에서 방으로 들어오는 따뜻한 햇빛 방향광과 그림자, 부드러운 창빛·바닥 창 모양 빛을 추가했다. 환경광을 높이고 책상등 강도를 낮춰 밤처럼 칙칙한 상태를 줄였다. 비 없는 상태와 기존 주제별 작은 행동은 유지한다.

미래 계획 대신 이미 이뤄진 일상 대사로 변경했다: 드디어 이거 보네 / 먹고 싶던 거 드디어 먹는다 / 첫 작업 내 손으로 끝냈다 / 아빠 내가 번 돈으로 산 첫 선물이야 / 이번 달 월세 내 돈으로 냈다. 모두 체험용 창작이며 원문 발췌로 표시하지 않는다. 멘트는 4.2초 행동 완료 이후 나타나고 기존 14초 엔딩·크레딧 흐름을 유지한다.

## 소리 연출 · 2026-11-10 최신

`/local/`에 장면별 소리를 붙였습니다. 정상 면접은 음악 없이 에어컨 실내 소리와 시계 초침을 반복하고, 새 질문마다 종이 넘기는 소리를 냅니다. 행복버튼으로 전환되면 합성 "뿅" → 레코드 긁힘 → 유리 금 소리와 함께 실내 소리가 끊기고, 약 1초 뒤 132 BPM 합성 비트(킥·하이햇)가 시작됩니다. 면접관이 반박할 때마다 책상 치는 소리와 짧은 금관 화음이 나고 베이스 → 박수 → 16분 하이햇·화음 순으로 악기가 쌓입니다. 종료 시 비트를 끊고 실내 소리로 돌아갑니다(문밖 여정이 있는 화면에서는 여정 쪽 퇴장 문소리만 냅니다). 대사 저격 명중에는 파열음·몸통 잡음·낮은 쿵·유리 꼬리를 압축해 묶은 큰 총소리를 내고, 그 순간 음악을 잠깐 눌러 타격을 돋보이게 합니다. 마지막에 리미터를 두어 효과음이 겹쳐도 소리가 찢어지지 않습니다.

`local/sound.js`가 `interview:state`를 듣고 상태 변화를 소리 신호로 바꿉니다(`transitionCues`, 순수 함수). 저격 명중은 `game.js`가 보내는 `interview:shot`으로 받습니다. 면접관 음성(`body.speaking`) 중에는 음악과 실내 소리를 낮추고, 공간 보기·얼굴 편집·여정 일시정지 중에는 음악과 실내 소리를 먼저 내리고, 책상·총소리 같은 단발 효과음 꼬리가 끝난 약 1.6초 뒤 오디오를 멈춥니다(탭 숨김은 즉시 멈춤). 상단 **효과음 켜짐/꺼짐** 버튼은 기존 **음성** 버튼과 별개입니다. 첫 클릭 전에는 브라우저 자동 재생 제한 때문에 소리가 나지 않습니다.

효과음 7개는 Freesound **CC0** 미리듣기 MP3이며 출처와 라이선스 확인 기록은 `assets/sfx/CREDITS.md`에 있습니다. 비트·버튼음·화음은 Web Audio로 합성해 파일이 없습니다. 새 패키지·외부 요청은 없습니다.

검증(소리 추가 당시): 구문 검사와 전체 테스트 **60개 통과**(`local-sound.test.js` 2개 추가). headless Chromium에서 로컬 대사 모드로 착석→답변 2회→행복버튼→저격 키 1→반박 4회→종료를 진행하며 Web Audio 출력만 녹음해 0.5초 단위로 측정했습니다. 실내 소리 약 -46dB, 행복버튼 순간 약 -17dB, 비트 약 -24dB(음성 중 약 -32dB로 낮아짐), 반박·종료 효과음의 순간 피크를 확인했습니다. 기기 TTS 음성은 Web Audio 밖이라 녹음에 포함되지 않아 실제 스피커에서의 음성 대비 음량은 귀로 확인이 필요합니다.

## 대사 저격 + Bithumb 서체 · 2026-11-10 최신 실험

저격 대상은 버튼 대신 **면접관의 현재 대사**로 정리했습니다. 사용자 제공 `bithumb_gothic_otf.zip`에서 Basic/Original OTF를 찾아 내용 변경 없이 보존·복사했습니다. 행복버튼 전에는 Bithumb Basic으로 대사를 읽고, 이후에는 Bithumb Original로 바뀐 대사가 공중에 떠서 조준·클릭하면 글자 파편으로 흩어집니다. 긴 대사는 3개씩 띄우고 나머지를 순서대로 이어서 내용을 빠뜨리지 않습니다. 새 반박이 오면 현재 대사로 교체합니다. 종료 후에도 Original을 유지하고 다시 앉으면 Basic으로 돌아옵니다.

실험 방법: **로컬 대사로 시험 → 두 번 답하기 → 행복버튼 → 떠오른 대사 조준·클릭**. 입력창 밖에서는 1·2·3도 사용할 수 있고, Tab으로 저격 버튼에 접근할 수 있습니다. 답변/마이크는 계속 사용할 수 있으며 저격 자체는 AI를 호출하거나 답변·분노 횟수를 바꾸지 않습니다. 기존 면접실·캐릭터·충격/붉어짐·대화 흐름은 유지합니다. 공간/얼굴 편집 중 저격을 멈추고 복귀 시 이어가며, 동작 줄이기에서는 부유·파편 없이 글자를 없앱니다.

JPG·PNG·WebP, 12MB 이하를 지원합니다. 두상과 머리카락은 유지되고 얼굴 표면의 외형을 교체합니다. 얼굴 사진이 있는 입체 모델이며 사진 한 장으로 정밀한 개인 두상을 복원하는 기능은 아닙니다. 현재 의상·손·헤어·얼굴 일치도는 1차 모델 수준이고 포토리얼 완성본은 아닙니다. 실제 브라우저 화면은 환경 제약으로 미검증입니다. [전략·원본·한계](references/character-source/README.md), `character-verification.json` 참고. 대화 시제품과의 연결·표정 애니메이션은 아직 없습니다.

## 면접관 대화 시제품

Node.js 24 이상에서 `npm start` 후 http://127.0.0.1:4173/interview.html 로 접속합니다. 이미 서버가 실행 중이면 서버 코드를 반영하기 위해 해당 서버를 재시작하세요. 다른 프로세스를 임의로 종료하지 않습니다.

- 답변을 입력하거나 마이크로 말한 뒤 수정해서 보낼 수 있습니다. 음성 인식 중 키보드로 편집하면 인식을 멈춰 수정 내용을 지킵니다. 마이크를 다시 누르면 말하기가 끝납니다. Enter로 전송, Shift+Enter로 줄바꿈합니다.
- 평소에는 정중하게 근거를 요구합니다. 두 번 답한 뒤 행복버튼이 켜집니다. 버튼 이후 다음 답변부터 내 말에 발끈하며 맞받아치는 면접관으로 전환됩니다. 사용자 편에 서서 함께 화내는 인물이 아닙니다.
- 시제품 기준 정상 답변 최대 5회, 버튼 이후 최대 4회입니다. 어느 때든 면접 마치기로 끝낼 수 있습니다. 수치는 `interview-service.js`의 `limits`에서 조정합니다.
- AI 키가 없으면 **로컬 대사 시험**을 명시적으로 골라 흐름을 확인할 수 있습니다. 사전 작성 대사를 키워드로 선택하는 모드이며 AI 모델 성능을 검증하지 않습니다. AI 호출 실패를 조용히 로컬 대사로 대체하지 않습니다.
- 말하기는 Web Speech API의 브라우저 음성 인식입니다. 브라우저·권한·한국어 지원에 따라 사용하지 못할 수 있으며, 입력으로 계속할 수 있습니다. 면접관 음성은 기기에 설치된 한국어 음성 읽기를 사용하고 감정 연기·목소리 높낮이 제어는 제한적입니다. 음성 API 요금은 발생하지 않으며, 브라우저의 인식 서비스가 외부로 음성을 전송할 수 있습니다.
- 이번 시제품은 대화만 시험합니다. 기존 3D 파괴 장면, 수집한 어구·근로 동기 데이터와의 연결은 아직 추가하지 않았습니다. 로컬 대사와 AI 대사는 허구의 면접관 연출입니다.

### 실제 AI 연결

`.env.example`을 `.env`로 복사한 뒤 자신의 OpenAI API 키를 `OPENAI_API_KEY=` 뒤에 설정하고 `npm start`를 다시 실행합니다. 키를 채팅에 붙여넣거나 프런트엔드 코드에 넣지 마세요. 기본 모델은 `gpt-6-luna`이며 `INTERVIEW_MODEL`로 변경할 수 있습니다. 선택 모델이 Responses API 및 `reasoning.effort: none`을 지원해야 합니다. 키와 모델의 계정 이용 권한·잔액은 별도 필요합니다.

서버가 답변과 해당 대화 이력을 OpenAI Responses API로 보냅니다. 요청은 `store:false`, 출력 최대 200토큰이며 자동 재시도는 없습니다. 실패한 시도를 포함해 세션당 API 요청은 최대 12회입니다. 성공 응답이 유실돼 다시 전송하면 같은 요청 ID로 결과를 재사용합니다. 실제 사용량은 접힌 기록에서 확인할 수 있습니다. 서버는 이력을 메모리에만 보유하며 종료 때 삭제하고, 마지막 활동 후 20분이 지나면 최대 30초 내 정리합니다. 앱이 파일에 저장하지 않는다는 뜻이며 공급자의 데이터 처리 정책과 동일한 의미는 아닙니다.

공식 문서: [모델](https://developers.openai.com/api/docs/models/gpt-6-luna), [텍스트 생성](https://developers.openai.com/api/docs/guides/text-generation), [브라우저 음성 인식](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition), [브라우저 음성 읽기](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis).

### 대화 검증 범위

`npm run check`, `npm test`: 기존 3개를 포함한 18개 테스트 통과. 서버 모드 전환·입력 제한·호출 실패·재전송·이력 삭제와 HTTP 처리기를 검증했습니다. 클라이언트는 경량 DOM·음성 이벤트 대역으로 여러 턴·전환·종료·재시작·음성 수정 충돌을 검증했습니다. 실제 브라우저 렌더링 검증을 대체하지 않습니다. 현재 환경은 포트 바인딩·자동화 브라우저 실행이 제한됐고 앱 브라우저 연결도 사용할 수 없었습니다. 실제 화면·마이크·음성 출력·모델 응답 품질과 지연·실비는 아직 검증하지 못했습니다. API 키도 미설정 상태입니다.

## 실행

Node.js 24 이상이 설치된 Mac에서 `면접실 실행.command`를 실행합니다. 또는 이 폴더에서 다음을 실행한 뒤 브라우저로 접속합니다.


접속 주소: http://127.0.0.1:4173

Three.js와 재질 파일을 프로젝트 안에 포함했으므로 실행할 때 패키지를 설치하거나 외부 CDN에 접속할 필요가 없습니다. `index.html`을 파일로 직접 여는 대신 로컬 서버를 사용하세요. 로컬 컴퓨터에서만 접근하도록 서버를 구성했습니다.

## 행복버튼 체험

1. 시작하면 ‘왜 지원하셨나요?’라는 질문이 나옵니다. 계기·경험·마무리에서 어구를 하나씩 고릅니다.
2. **답변하기**를 누르면 면접관의 정해진 재질문이 나오고 **행복버튼**이 활성화됩니다.
3. 행복버튼을 누르고 하고 싶은 새 답변을 고르거나 140자 안으로 직접 씁니다.
4. 기존 어구 세 개를 겨냥해 클릭합니다. 파편·타격음과 함께 새 문장 조각으로 바뀝니다. 키보드 1·2·3으로도 해당 어구를 부술 수 있습니다.
5. 세 어구를 모두 부수면 새 답변을 다시 고칠 수 있습니다. **이 말로 답하기**로 제출합니다.
6. 결과 화면에서 **다시 해보기**를 누르면 처음부터 체험할 수 있습니다.

상단 ‘면접실 보기’로 기존 공간 조작 메뉴를 사용할 수 있습니다. ‘면접으로 돌아가기’로 복귀합니다. 소리는 상단 버튼으로 끌 수 있으며, 외부 음성 API 호출은 없습니다. 모범답안 어구는 수집 자료를 바탕으로 편집했고, 행복버튼 이후 선택지는 창작 예시입니다. 출처는 체험 화면에서 확인할 수 있습니다. 답변을 저장하거나 외부로 전송하지 않습니다.

`game.js`는 조작 화면·3D 어구·파편·효과음을, `flow.js`는 체험의 상태 전이를 담당합니다. `npm test`로 상태 전이·입력 제한·재시작 검증을 실행합니다. 실제 브라우저에서는 마우스 명중, 선택지 및 직접 쓴 답변의 제출, 초기화, 공간 보기 왕복을 확인했습니다.

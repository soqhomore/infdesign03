## 통합 버그 점검·3D 반응·UI 마감 · 2026-11-10 최신

사용자가 자리를 비운 동안 버그 수정, 과제 적합성 검토, 행복버튼 이후 카메라·면접관 반응 강화, 3D/UI 마감을 순서대로 요청했다. 기존 /local/ 흐름과 공개 점검 화면은 유지하며 푸시·배포·유료 음성 연결은 하지 않았다.

대기실 마이크가 메뉴/자료/선택/수정 뒤에도 문장을 덮던 문제, 행복 전환 중 메뉴 복귀 때 대화·저격 잠금이 먼저 풀리던 문제, 공간/얼굴 보기에서 대기실 소리가 남던 문제를 재현 후 수정했다. 전환 중에는 버블·효과음만 재개하고 TTS·저격은 계속 잠그는 conversationPaused 신호를 사용한다. 최종 면접관 답변이 한 프레임도 보이지 않고 즉시 퇴장하던 흐름도 고쳐, 실제 마지막 응답은 3~9초 읽을 시간을 주고 음성 재생 중이면 최대 12초까지 기다린다. 명시 종료는 바로 퇴장한다.

행복버튼에는 실제 3D 카메라의 유한 충격과 시야각 변화, 실제 반박 응답부터는 단계별 접근을 추가했다. 면접관은 허리 위 몸통·팔·머리가 함께 들썩이고 더 크게 떨되 다리/착석은 유지한다. 손의 상판 관통 방지, 시선과 사진 의상 매핑 유지, 초기화/일시정지/동작 줄이기 복원을 검증했다. 카메라 줌과 AO 깊이 복원 행렬도 매 프레임 동기화한다. 카메라 모듈은 현재 서버에서 바로 제공되는 assets/demo/camera-drama.js에 있다.

과제의 A 추천 답변/B 다양한 취업 이유 관계를 검토하고 자료 창을 질문 종류·주제·출처별 묶음으로 정리했다. 대기실은 왜 일하고 싶어요?로 질문을 넓혔다. 통계·순위·진심 판정은 추가하지 않았고 크레딧에 생활 장면과 끝 대사의 창작 표시를 보강했다. 실제 면접 대사는 A 원문이 아니라 창작이며 A는 선택적인 자료 창에 있다는 한계는 남는다.

침대 받침·러그·봉제선·창밖 맑은 하늘·벽 하단을 추가하고 글자 블록/선택 문장/답변창/행복버튼/모바일·짧은 화면/포커스·자료 창의 대비와 여백을 정리했다. 기존 비 없는 햇빛·작은 성취 엔딩과 지정 폰트는 유지한다.

## 음성 누락·진단 보완 · 2026-11-10 최신

면접관 음성 출력은 외부 TTS가 아니라 브라우저/기기의 한국어 SpeechSynthesis를 사용한다. 코드 재현 검사에서 일시정지 중 도착하거나 끊긴 대사를 복귀 후 읽지 않는 경로, 아직 비어 있는 voiceschanged 이벤트를 한 번 받은 뒤 음성 로딩을 포기하는 경로를 확인했다. 최신 대사만 복귀 후 한 번 읽도록 보완하고, 한국어 목소리를 최대 3초 기다리되 중간 빈 이벤트는 무시한다. 완료한 대사는 반복하지 않으며 음성 끄기·제출·초기화 때 대기 중 대사를 폐기한다.

일시정지 설정에 목소리 시험과 선택된 목소리/재생 상태를 추가했다. 시험 음성은 메뉴가 열린 동안에도 재생할 수 있고, 복귀 시 시험을 끊고 보류된 면접 대사를 읽는다. 재생 차단·네트워크·한국어 음성 미확보를 안내한다. 시작 실패 시 한 번만 재시도하고 끝내 실패하면 알리며, 종료/취소 이후 늦은 음성 이벤트를 무시한다. 기존 자연스러운 기기 음성 우선순위는 유지한다.

검증: npm run check 통과, npm test 전체 97개 통과. 실제 사용자 기기의 무음 원인을 확정한 것은 아니다. 브라우저 접근 호스트가 연결되지 않아 실제 음성 출력·마이크·WebGL은 이번 작업에서 미검증이다. voice-verification.json 참고. 이전 버그·성능 점검의 1.5초/한 번의 이벤트 대기와 복귀 후 다음 발언부터 재생한다는 설명은 이전 상태다.

자연스러운 목소리는 고정 대사를 미리 생성/녹음한 파일로 재생하고, 동적 AI 답변만 서버 TTS로 읽는 방식을 제안한다. 감정 연기를 지원하는 ElevenLabs 등을 후보로 조사했지만 사용자 확정이나 서비스 연결·유료 호출은 하지 않았다. 공급자/목소리별 실제 한국어 청취가 필요하다.

대표적인 내용: 집을 사기 전 친구와 커피·미술 수업·주말여행을 미룸, 감량 전 보컬 수업·댄스 영상·데이트를 미룸, 감량 후 원하던 옷을 입음, 더 좋은 직장→이사→저축→덜 바쁜 삶으로 출발 조건이 계속 이동함. 원문 해석에는 각 행의 판독 메모가 우선한다.

## 3. 현재 기획으로 이동한 과정

다음은 역사적 맥락이다. 별도 요청 없이 현재 기능에 다시 넣지 않는다.

1. **미뤄 둔 생활이 있는 방/움직이는 배경화면**: 어시스턴트 제안. 사용자는 ‘그런 느낌보다는’이라며 다른 방향을 설명했다. 현재 방향으로 채택하지 않았다.
2. **비슷한 바람이 모이는 배경·공동 작업장**: 사용자가 원한 대안. 목표를 입력하면 같은 목표나 바람을 가진 사람들이 모이는 공부방·가상 여행 등. 가상에서 취업을 시켜 준 뒤 여행을 보내는 안도 검토했다. 현재 MVP에는 없다.
3. **취업 준비 교재를 찾아 가상에서 찢기**: 사용자 제안. 책 정보와 수험 과정의 양가감정을 연결할 수 있다고 논의했다. 제목·표지·ISBN·판본·쪽수·목차·가격·홍보 기간·리뷰 등을 검토했지만 책 데이터의 실제 대량 수집은 하지 않았다. 현재 기능이 아니다.
4. **면접관에게 못 했던 말 하기**: 사용자 제안. 질문/행동과 지원자의 공개 반응을 연결하는 공개 사례를 검색했다. 정확한 ‘그 질문을 받은 당사자의 못 한 말’을 대규모로 확보한 것은 아니다. 당시 답·뒤늦은 말·제삼자 댓글을 섞으면 안 된다고 정리했다. 별도 정식 데이터셋은 만들지 않았다.
5. **모범답안을 모아 부수기**: 사용자가 제안해 현재 기획의 기반이 됐다. 지원자를 면접용 문장에 맞추는 틀을 부수는 쪽으로 초점이 이동했다.

‘취업하면 여행하고 싶다’는 글만으로 ‘취업 준비를 때려치우고 싶다’고 해석하지 않는다. 서로 다른 단계의 데이터와 주장을 합쳐 검증된 결론처럼 만들지 않는다.

## 4. 현재 확정된 경험과 메시지

### 사용자가 확정한 내용

- 모범답안 **어구 부수기**가 중심.
- 아이템 선택·면접관에게 던지기는 제외. 스케치 속 로켓·페인트볼·토마토·계란은 과거 구상이다.
- 오른쪽의 ‘최후의 수단’은 **‘행복버튼’**으로 이름과 역할을 변경.
- 버튼 이전에는 나오는 모범답안 어구들을 선택해 답변한다.
- 버튼 이후에는 그 어구를 냅다 부수고 **내가 하고 싶은 새로운 답변**을 선택할 수 있다.
- 단간론파 쪽의 문장 조준·명중·파괴 인터랙션을 참고.
- 실제 실행되는 3D 면접실이어야 한다. 사진 구도를 유지하며 재질·쉐이더·조명을 최대한 사실적으로 만들고 싶다.
- 인물은 나중에 넣는다. 현재는 공간과 질문 하나의 핵심 경험만 구현 요청했다.

### 작업을 설명하기 위해 제안된 메시지 문장

- ‘우리는 평가받는 자리에서, 하고 싶은 말보다 통과할 수 있는 말을 고른다.’
- ‘나를 설명하는 자리에서, 나는 남이 써 준 문장을 연습한다.’
- ‘합격하기 위해 고르던 말에서, 나를 위해 고르는 말로.’

이는 디자인을 설명하기 위한 문구다. 사용자들이 모두 거짓말한다거나 모든 모범답안이 유해하다고 검증한 연구 결론이 아니다. 최종 전시 카피는 아직 확정되지 않았다.

### 폐기·수정된 해석

어시스턴트가 ‘모범답안을 부수고 처음 직접 쓴 진심을 되찾기’를 제안했지만, 사용자가 정한 것은 **버튼 이후 새로운 답변을 고르는 방식**이다. ‘처음 문장으로 복원’이 핵심이 아니다.

AI가 문장을 판독해 진심/가식을 가르면 안 된다. 추천에서 가져온 말과 직접 선택·작성한 말을 기록으로 구분할 수는 있으나 진정성을 판정하지 않는다. 후반 선택지를 욕·비꼬기만으로 채우지 않고 돈·생활·흥미·휴식 같은 이유도 두자는 것은 어시스턴트의 설계 제안이며 현재 예시 문구에 반영했다.

## 5. 모범답안 데이터: 무엇을 실제로 모았나

### 단점 질문: `data/model-answers/collected_answers.json`

- 같은 질문군 ‘본인의 단점은 무엇인가요?’에서 추천 예시 **12개 / 출처 페이지 8개**.
- 장단점 통합 질문의 단점 예시도 포함. 한국어와 영어가 섞여 있다.

- 출처당 짧은 직접인용 + 조사자 한국어 요약, 약점·개선 행동·결과와 URL/위치 정보를 보존했다.
- 이 표본의 12개 모두 개선 행동을 붙인다. 5개는 꼼꼼함·세부 사항·완성도 때문에 시간이 걸리는 패턴으로 분류했다.
- 초기 검색에 완벽주의·꼼꼼함이 들어갔으므로 5/12를 전체 모범답안의 빈도로 일반화하면 안 된다.
- 완벽주의를 피하라는 가이드와 완벽주의에 개선 행동을 붙여 추천하는 가이드가 공존한다.

### 한국어 지원동기·퇴사 이유: `data/model-answers/한국어_지원동기_퇴사이유_17개.json`

- **17개 예시 / 9개 페이지 / 7개 사이트**.
- 지원동기 **8개 / 4개 페이지**: 인크루트, HAIJOB, 잡패스코치(jobready), 링커리어.
- 퇴사·이직 이유 **9개 / 5개 페이지**: Deel 한국어판, 링커리어, CrawlJobs 한국어판, 프리터뷰, 잡패스코치(jobready).
- 한국어 제공 자료이며 모두 한국어로 처음 작성됐다는 뜻은 아니다.
- 같은 사이트의 여러 예시는 독립 발행처로 세지 않는다. 상호 재인용·독립 저작 여부까지 검증하지 않았다.
- 실제 지원자 발언·합격 여부·면접관 의도의 진위는 검증하지 않았다. 가이드가 추천한 예시·템플릿을 수집한 자료다.
- 금지 예문/나쁜 답변은 추천 표본에서 제외했다.
- 페이지별 직접인용은 25단어 이내로 제한했다. 전체 모범답안 원문을 무제한 복제한 코퍼스가 아니다. 비교할 전체 문장은 출처에서 다시 확인한다.
- `original_excerpt`는 인용, `summary_ko`·`structure`·`subtype`은 조사자 해석이다.
- `observed_terms`는 원문에서 확인한 일부 분석용 어근·문구 목록이지, 자동 전수 단어 빈도표가 아니다.

### 확인한 반복과 차이

지원동기에서는 회사 특징 → 내 경험/역량 → 기여 또는 성과로 이어지는 구조가 반복됐다. 8개 예시 안에서 ‘기여하고 싶습니다’가 정확히 4개, ‘기여를 하고 싶습니다’가 별도 1개였다. 현재 게임의 세 슬롯은 이런 구조에서 편집한 것이며, 실제 문서 전체의 빈도 순위를 그대로 구현한 것은 아니다.

퇴사 이유에서는 성장·역량·환경·성과 같은 어휘와, 과거 배움 → 현재 한계 → 다음 환경으로 넘어가는 구조가 반복됐다. 모든 답이 동일하거나 부정적인 실제 사유를 모두 숨긴다는 뜻은 아니다.

특히 링커리어의 연봉 상황 예시는 성장·역량 환경의 언어로 우회하도록 제안하는 반면, 프리터뷰의 가상 예시는 보수가 이유라고 직접 밝히고 업무 범위·직무 등급의 불일치를 설명한다. 이 차이도 보존해야 한다. 자료의 ‘직접 언급 금지’ 조언을 우리 프로젝트의 취업 권고로 반복하지 않는다.

## 6. A·B 연결의 현재 상태

이전 SNS 수집에서는 A=출발 조건, B=미뤄 둔 생활이 명확했다. 현재 면접 프로젝트의 A·B는 논의 중 **‘같은 면접 질문과 여러 출처의 추천 답변’**으로 이동했다.

현재 시연에서는 질문과 앞쪽 어구가 수집 자료와 연결되지만, 행복버튼 이후의 답변은 창작이다. 따라서 **‘추천 답안 데이터 A × 사람들의 실제 속마음 데이터 B를 실증했다’고 발표하면 안 된다.** 수업에서 독립된 두 데이터가 요구되는지, 질문·답안 연결만으로 충분한지 아직 다시 확정하지 않았다. 필요하면 공개 면접 후기·지원 동기의 현실적 이유 등을 별도 수집해야 하지만 아직 승인된 후속 작업은 아니다.

또한 현재 런타임은 17개 JSON을 로드하거나 어구 빈도를 자동 계산하지 않는다. `flow.js`에 편집된 어구와 창작 답변을 넣었다. ‘수집 자료를 기반으로 한 프로토타입’이 정확한 설명이다. 확률·공감률·합격률 같은 수치는 화면에 넣지 않았다. 이후 어구 출현 수를 보인다면 분모와 표본·편집 기준을 명시해야 한다.

사용자가 첨부한 화면은 인물을 중심으로 문장이 겹쳐 나오며, 핵심 단어가 노란색 등으로 강조되고 원형 조준 표시가 있다. 기울어진 프레임, 우측 타이머/상태 표시, 하단 탄환 같은 말의 선택 UI가 보였다. 사용자는 이 **조작감**을 참고하자고 했다. 작품의 원본 아트·음원·폰트·아이콘을 복제하라는 요청은 아니다.

### 면접실 사진 — 원본 이미지 파일 미확보

16:9에 가까운 정면 사진. 지원자 눈높이에서 세 사람이 일렬로 앉아 있다. 왼쪽은 회색 재킷 남성, 가운데는 남색 재킷/흰 셔츠 남성, 오른쪽은 어두운 핀스트라이프 재킷 여성. 밝은 파란 연결 책상이 아래쪽을 크게 차지한다. 각자 서류·필기구, 책상에 작은 검정 마이크 두 개. 뒤에는 거의 내려온 회색 롤 블라인드와 얇은 세로 창틀·밝은 틈, 갈색 목재 창턱, 아래와 왼쪽 가장자리에 벽돌. 천장·바닥이 두드러지지 않는 구도다. 현재 구현은 이 구도에서 사람을 뺀 공간을 재현한다.

### 생성 시안과 실제 구현의 구분

`references/visual-targets/generated-room-target-v1.png`는 어시스턴트가 만든 이미지다. 사용자는 이미지가 아니라 실행되는 3D를 원한다고 정정했다. 이 이미지는 조명·재질 목표의 참고일 뿐 **원본 사진 또는 구현 결과가 아니다**. 실제 공간은 `scene.js`가 만들고 렌더링한다.

초기 영상 `references/early-concept/1080x1620.mp4`는 최초 감정적 정보디자인의 참고로 언급됐다. 현재 면접 인터랙션의 직접 구현 명세로 분석하지 않았으므로 영상의 구체적 의미를 추측하지 않는다.

## 8. 검토했던 도구·스킬·기술 선택

사용자가 보낸 저장소:

- https://github.com/skinnye/generative-art-pack — 생성 아트·입자·GLSL 참고.
- https://github.com/charlie947/motion-graphics-skills — 타이포·전환·모션 영상 참고.
- https://github.com/dotslashsimran/simcraft — Three.js/GLSL 반복 영상·분석·기술 보조 참고.

추가로 검토한 https://github.com/skinnye/3d-web-pack 은 실행 장면·에셋 최적화·후처리가 더 직접적이라고 안내했다. 이는 조사 당시의 적합성 판단이며 실제 품질 보증이나 설치 완료가 아니다. 사용자는 **추가 스킬 없이 구현**하라고 했고, 위 저장소는 프로젝트에 설치하지 않았다.

Spline 편집기 연결이 안 됐던 적이 있으나 현재 구현은 Spline에 의존하지 않는다. 기존 계정·연결을 사용자에게 요구할 필요가 없다. Node와 Three.js를 사용해 로컬에서 실행한다.

## 9. AI 면접관의 논의 상태

사용자는 ‘면접관스럽게 몇 마디만, 최대한 싸게’ 동작시키고 싶다고 했다. 별도 파인튜닝보다 역할·예시 프롬프트, 준비된 반응 선택, 고정 음성 재생, 필요할 때만 음성 인식/짧은 분류를 제안했다. 준비 대사 20~30개와 꼬리질문 최대 두 번 등의 수량은 어시스턴트의 제안이고 확정 구현량이 아니다.

현재는 **고정 질문 한 개, 고정 재질문 한 개, 코드 생성 효과음**이다. LLM·STT·TTS·대사 선택 모델·음성 녹음은 연결하지 않았다. 실제 AI 기능이나 API 과금이 있다고 말하면 안 된다. 당시 언급한 모델 가격은 시점 의존 정보이므로 연결할 때 공식 자료로 다시 확인한다. 어떤 모델을 최종 채택할지는 미정이다.

## 13. 사용자 승인한 다회 대화 시제품

이후 사용자는 면접이 한 질문으로 끝나는 흐름을 정정하고, 여러 차례의 직접 문답 도중 행복버튼으로 흐름을 깨길 원한다고 확정했다. 말하기와 입력하기를 모두 지원하며, 평소 정중하게 근거를 요구하는 면접관이 버튼 이후 내 말에 발끈하고 맞받아친다. 내 편이 되어 회사에 함께 화내는 역할이 아니다. 사용자는 대화 시제품부터 만들고 나중에 3D와 연결하는 진행에 승인했다.

`/interview.html`에 별도 대화 시제품을 구현했고 원래 3D 흐름은 보존했다. 기본 모델·브라우저 음성·2회 후 버튼·정상 5회/발끈 4회·600자·출력 200토큰·호출 12회 한도는 구현자가 비용과 범위를 고려해 정한 조정 가능한 값이다. 새 시제품의 AI 모드는 답변·이력을 외부 API에 전송한다. 원래 게임의 외부 전송 없음과 구분한다. 키 없이 고르는 로컬 대사는 창작된 규칙 대사다. 수집 자료의 빈도나 실제 사람의 진심을 모델이 판정하지 않는다.

이번 환경에서는 키가 없고 포트·브라우저 제약이 있어 실제 모델·화면·음성 품질을 확인하지 못했다. 최신 실행 안내와 검증 범위는 README와 HANDOFF 최신 변경 절, `dialogue-verification.json`을 따른다. 과거 9절의 AI 미연결 상태는 원래 3D MVP에 대한 기록으로 읽는다.

## 추가 다운로드 없는 가운데 면접관 재구성 · 2026-11-10

사용자는 자산 다운로드가 어려워 다른 방법을 요청했고, 기존 CC0 전체 인체 원본을 활용하는 권장안을 승인했다. 가운데 한 명의 몸·팔·손을 같은 표면으로 착석시키고 체형에 맞는 의상을 직접 제작했다. 가운데 의상에는 사진을 투영하지 않는다. 양옆 몸체는 기존 방식이며 왼쪽 누락 셰이더 수정은 유지한다. 로컬 사진 교체·다회 대화 반응과 방·카메라·조작은 유지한다. 공개 점검 화면 해제·푸시·배포는 요청 범위가 아니다. 형상 CPU 점검과 자동 테스트를 실제 WebGL 외관 검증으로 설명하지 않는다. 최신 검증은 offline-character-verification.json을 따른다.

## 얼굴 세 가지 선택 · 2026-11-10

사용자는 실제 얼굴의 부조화를 지적하고 사람 얼굴을 쓰지 않는 대안을 열었다. 제안한 무표정 회백색 가면에 카피바라 마스크와 사용자가 넣은 사진을 더해 선택할 수 있도록 요청했다. 기본은 세 인물 모두 회백색 가면이며 메뉴에서 면접관별 선택한다. 사진은 이전 해부학 두상 대신 완만한 곡면 가면에 투영한다. 사진을 업로드해 적용하기 전 실제 외형은 유지하며, 기본/카피바라 왕복 중에는 사진을 보존하고 초기화/새로고침 때 제거한다. 얼굴 선택으로 면접 세션을 새로 시작하지 않는다. 기본/카피바라 눈썹은 다음 반박 응답부터 기울어지며 사진은 고개 반응만 따른다. 실제 개인 두상 복원·립싱크는 범위가 아니다. 최신 자동 검증 45개 통과, CPU 형상 확인; 실제 WebGL 외관 미검증.

## 세 면접관의 주시와 소동작 · 2026-11-10

사용자가 세 명 모두 자신을 바라보고 간헐적으로 조금씩 움직이도록 요청했다. 기존 지원자 위치를 목표로 삼아 모든 얼굴을 향하게 하고 독립적인 짧은 고개 동작을 추가했다. 몸체/방/카메라/외형 선택/다회 대화는 유지한다. 고개 변환은 character controller에서 시선·idle·감정 자세를 합성하며 stage가 중복 덮어쓰지 않는다. 동작 중만 최대24fps로 다시 그리고 정지 프레임을 재사용한다. 얼굴 편집 중 idle을 멈추고 reduced-motion을 따른다. 실제 브라우저 움직임은 아직 미검증이며 CPU 시뮬레이션을 실제 FPS로 부르지 않는다.

## 행복버튼 연출 강화 · 2026-11-10

사용자가 행복버튼 순간의 화면 흔들림과 갈수록 부들거리고 붉어지는 면접관 등 더 극적인 연출을 요청했다. 버튼 순간은 플레이어 화면 충격/버튼 자리의 금빛 잔상·고리이며, 면접관은 다음 사용자 말에 대한 반박부터 angryTurns 단계에 따라 붉어지고 떨린다. 가운데가 중심, 양옆은 약한 동조다. 기본/카피바라/사진 모두 열감을 표현하며 사진 원본은 변경하지 않는다. 부들거림은 답변별 유한 burst로 기존 시선/소동작과 합성하고 끝나면 복귀한다. 다시 앉기는 열감·연출을 초기화한다. 카메라 원본/데이터/대화 구조/공개 점검 페이지는 바꾸지 않았다. 테스트53개와 CPU 색/형상 검증은 실제 CSS/GPU 외관을 증명하지 않는다.

## 대사 저격과 Bithumb · 2026-11-10

버튼 자체를 저격하는 직전 요청은 읽기 단계에서 중단됐고 구현하지 않았다. 사용자는 대사를 저격하는 연출로 다시 구성하고 제공한 bithumb 파일을 사용해 행복버튼 전 Basic, 후 Original로 바꾸도록 요청했다. ZIP을 학과 정보디자인 폴더에서 찾아 원본/두 OTF를 보존했다. 현재 대사를 마디로 나눈 공중 텍스처를 조준·파괴하는 로컬 실험을 연결했다. 대사는 생략하지 않고 3개씩 순차 표시하며, 저격이 답변 전송/AI 요청/분노 횟수를 대신하지 않는다. 기존 다회 대화·캐릭터 반응·공개 점검은 유지한다. 실제 서체 native Canvas 렌더 및 Three 조준·상태 테스트를 실제 브라우저/GPU 확인으로 설명하지 않는다. 현재 단계는 시제품 실험이다.

# 면접실 통합 점검·과제 검토

2026-11-10. 사용자가 자리를 비운 동안 버그 → 과제 적합성 → 행복버튼 반응 → 3D·UI 순으로 진행한 작업이다. 원본 작업 폴더를 수정했으며 푸시·배포·외부 음성 서비스 도입은 하지 않았다.

## 과제 주제에 맞는가

검토 기준은 수업 피드백의 정보 전달, 불필요한 정보 제거, 도전적인 시도 세 가지다.

**정보 전달:** 방향은 맞다. A는 면접 가이드가 추천하는 말, B는 일하고 싶은 다양한 개인의 이유다. 문밖에서 B를 직접 고르고 그 말을 행복버튼 이후 다시 가져오는 행동이 메시지를 만든다. 돈만 남기지 않고 경력·관계·가족·흥미·안정 등 여러 이유를 동등하게 만나는 현재 구성을 유지했다. 첫 질문을 ‘왜 일하고 싶어요?’로 넓히고, 자료 창은 A / B / 주변 맥락을 구분한 묶음과 주제 표시로 정리했다.

**한계:** 본 면접의 AI·로컬 대사는 창작 연출이다. A 원문으로 생성되거나 실제 면접관 요구를 조사한 결과가 아니다. A 자료는 선택적으로 여는 자료 창에 있으므로, 모든 사용자가 본 체험만으로 A의 자료적 근거를 읽게 되는 것은 아니다. 이 부분을 과제 설명에서 과장하면 안 된다. ‘A는 거짓, B는 진심’ 혹은 ‘같은 사람의 겉말과 속말’로도 단정하지 않는다.

**불필요 정보:** 본 면접에는 긴 안내·통계·순위·판정을 추가하지 않았다. 자세한 수집 설명은 자료 창의 펼침 안내에 보존했다. 실제 발언과 창작 생활 장면을 혼동하지 않도록 크레딧 끝에 창작 표시를 추가했다. 여러 동기가 한 문장에 겹쳐 있는 원문과 출처 링크는 보존했다.

**도전성:** 외침·와이드 전환·글자 저격과 실제 3D 카메라/상체 반응이 다른 말하기를 몸으로 느끼게 한다. 버튼 자체에는 해방감을, 제출한 다음 답변에는 면접관의 발끈함을 배치했다. 파괴만 보상으로 남거나 합격/진심 점수로 읽히지 않도록 점수·교훈·평가는 추가하지 않았다.

엔딩은 사용자 확정대로 비 없는 햇빛과 이미 이뤄진 작은 생활이다. 수집한 작성자의 실제 후일담이 아니라 창작 장면이다.

## 행복버튼 이후 반응

- 버튼을 누르면 1.45초 버블 외침/와이드에 실제 카메라의 짧은 뒤로 튕김·좌우 충격·시야각 변화가 겹친다.
- 첫 실제 반박 응답부터 카메라가 점차 가까워진다. 전환 중 매우 빨리 답해도 반박 클로즈업은 외침 이후 시작한다.
- 면접관은 고개만 흔드는 대신 허리 위 몸통·팔·머리가 함께 반응한다. 좌우는 서로 조금 다른 타이밍과 강도다. 다리·착석 위치는 고정한다.
- 단계별 떨림은 이전보다 커지되 유한한 시간 뒤 잦아든다. 얼굴 열감은 기존처럼 누적한다.
- 손이 상판 아래로 들어가지 않도록 상체 높이를 보정하고, 몸통이 움직여도 사진 의상 매핑과 지원자를 보는 시선을 유지한다.
- 메뉴·편집·공간 보기·동작 줄이기에서는 카메라를 복원하고 시간을 멈춘다. 초기화 때 변형은 누적되지 않는다.

## 3D·UI 마감

- 침대 받침 네 개가 바닥과 프레임을 연결하고, 낮은 러그와 베개 봉제선을 추가했다.
- 창틀 뒤에 정적인 맑은 하늘과 먼 건물의 깊이를 만들고 벽 하단 마감을 추가했다. 외부 이미지 다운로드나 비 효과는 없다.
- 글자 블록·선택 문장·입력창·행복버튼의 대비와 여백을 정리했다. 고정 UI·글자 대비는 조용히 유지하고 강한 움직임은 행복 전환에 집중했다.
- 자료 창은 질문 종류·원문·출처·주제를 함께 읽도록 정리했다. 모바일/짧은 화면 입력창, 포커스, 스크롤을 보완했다.
- Pretendard/차이상승체와 행복 이후 Bithumb Original을 유지했다.

## 검증과 한계

`npm run check`, `npm test` 전체 106개 통과. `node scripts/verify-journey-lifecycle.mjs`의 마이크·전환·공간/얼굴 오디오 세 시나리오 통과. 독립 코드 리뷰와 UI/기하 리뷰에서 찾은 AO 동기화·자료 분류 문제를 회귀 검사 후 수정했다. 마지막 답변의 표시·일시정지·보류 음성 복귀도 재검토했다.

Chrome 실행은 ‘Target page/context/browser closed’로 실패했고 브라우저 접근 호스트도 연결되지 않는다. 따라서 실제 WebGL 명암·질감·모바일 배치·움직임의 체감과 기기 TTS/마이크 소리는 미검증이다. `character-drama-basic-1.png`는 방과 WebGL 셰이더를 제외한 CPU 기하 점검 이미지다. 실제 브라우저 캡처로 제시하지 않는다.

## 구현 판단 기록

- 사용자 부재 중 자율 진행 지시에 따라 별도 승인 대기는 두지 않았다. 기존 확정 흐름과 자료 원본은 보존했다.
- 카메라 모듈은 `assets/demo/camera-drama.js`에 두었다. 현재 실행 중인 서버도 허용하는 자산 경로를 사용해 서버 재시작 없이 새로고침으로 읽을 수 있게 했다.
- 기존 폴더에 미커밋 작업이 많으므로 새 체크아웃/전체 되돌리기/자동 커밋은 하지 않았다.
- 실제 화면 없이 큰 방 구조나 인물 메시를 새로 교체하지 않았다. 이번 마감은 접촉·관절·재질·UI 가독성처럼 범위를 확인할 수 있는 부분에 한정했다.

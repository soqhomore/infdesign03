# 면접관 대화 시제품 구현 계획

**Goal:** 말하기·입력하기를 오가며 여러 질문에 답하고, 행복버튼 이후 내 말에 발끈하는 면접관과 대화한다.

**Architecture:** 기존 3D와 별도의 `/interview.html`에서 대화를 먼저 검증한다. Node 서버가 대화 이력과 정상/발끈 모드를 관리하고 OpenAI Responses API를 호출한다. 브라우저 음성 인식·음성 읽기를 먼저 사용해 음성 API 비용을 줄인다. 실제 AI 키가 없을 때는 명시적으로 고르는 로컬 대사 시험을 제공한다.

**Tech Stack:** 기존 Node 24 HTTP 서버, 순수 HTML/CSS/JS, 브라우저 Web Speech, 서버 fetch.

**Spec:** 이 대화에서 사용자 승인: 음성/문자 전환, 평소 정중한 재질문, 행복버튼 이후 사용자에게 발끈하며 맞받아침. 기존 공간·파괴 구현을 보존하고 대화부터 검증한다.

## 제약과 구현 판단

- 새 의존성·학습·실시간 음성 스트리밍 없이 구현한다.
- 서버 키는 환경변수에만 두고 정적 서버는 공개 파일만 제공한다. 원문 기록은 서버 메모리에만 두고 삭제·만료한다. AI 요청에는 `store:false`를 보낸다.
- 정상 답변 2회 뒤 행복버튼 활성화, 정상 5회·발끈 4회 상한은 시제품의 조정 가능한 구현값이다. 버튼을 누른 직후에는 침묵하고 다음 사용자 답변에 화낸다.
- 입력 600자, 응답 최대 200토큰, 요청 제한·중복 전송 방지·타임아웃을 둔다.
- 화면은 현재 면접관 대사·현재 답변·마이크·전송·행복버튼 중심. 흐린 청회색 바탕과 먹색 글자, 행복버튼만 노란색. 발끈 모드에서는 선과 대사 색만 짙은 적색으로 변한다. 인물·새 3D·파괴 연출은 이번 대화 시제품에 추가하지 않는다.

## 검토할 실패 조건

- 빈 입력·너무 긴 입력: 이력과 호출량이 바뀌지 않는다.
- 버튼 조기 사용·브라우저의 모드 조작: 서버가 거부한다.
- 호출 실패·중복 전송: 답변을 잃지 않으며 같은 턴이 중복 저장되지 않는다.
- 재시작·음성 인식 지연 이벤트: 이전 요청과 음성이 새 대화에 섞이지 않는다.
- 환경변수·자료 파일·경로 탈출: HTTP로 노출되지 않는다.
